# SonarQube 개선 기록

## PRN-01 이미지 자원 해제 (2026-09-07)

기준 커밋은 `74d2ef3fe67327a5028080da7fd1c497d4de9e08`이며, `fix/sonarqube-resources`에서 작업한다. 공개 라이브러리 대상은 netstandard2.0, 기존 단위 테스트 대상은 net6.0-windows로 유지한다. NuGet 게시와 main 병합은 이 변경에 포함하지 않는다.

다섯 연결 방식(comport, driver, ethernet, lpt, usb)의 printphoto/sendpicture 세 overload는 연결 호출 이름을 정규화하면 각각 동일한 코드였다. 모두 내부 Bitmap을 해제하지 않았고, 사용하지 않는 Bitmap도 만들었다. 15개 메서드의 이미지 변환을 내부 BitmapCommand로 모아 동일한 소유권 규칙을 적용한다.

- 파일 경로로 읽은 원본과 내부 grayscale 이미지는 using으로 정상·실패 경로에서 해제한다.
- 호출자가 넘긴 Bitmap은 읽기만 하며 해제하거나 변경하지 않는다.
- 사용하지 않는 Bitmap 할당을 제거한다.
- grayscale 가중치·정수 절삭·128 임계값·MSB 순서·행 끝 흰색 padding·mode 0·좌표와 전송 호출 순서를 유지한다. 연결별 기존 CRLF 추가 동작도 유지한다.
- 공개 메서드/반환형, P/Invoke 선언, 연결 생성과 종료, 기존 static 공유 상태는 이번 배치에서 변경하지 않는다.

검증은 공용 테스트 26개(기존 4 + 신규 22)가 통과했다. 신규 테스트는 EventGate.Printer.Tests에서도 같은 소스를 연결해 .NET 8 소비자 CI에서 실행한다.

1. 기존 코드에서 LPT 인스턴스의 stream만 소유한 임시 파일로 바꿔 실제 전송 바이트를 확인한 뒤, 수정 코드에서 같은 golden bytes를 확인했다. 실제 프린터는 열지 않았다.
2. 파일 입력의 정상/헤더 실패/payload 실패/마지막 쓰기 실패에서 같은 예외를 전달하고 파일을 독점 읽기·쓰기로 다시 열 수 있음을 확인했다. 호출자 Bitmap도 실패 후 읽기·쓰기가 가능하다.
3. 1/8/9픽셀 행의 bit 순서/padding, 잘못된 이미지의 출력 없음, 연결하지 않은 Serial/TCP의 실패와 파일 잠금 해제를 확인했다.
4. 기존 lpt.cs만 되돌린 격리 빌드에서 정상/실패 × 두 파일 overload 테스트 네 개가 모두 파일 공유 위반 IOException으로 실패했다. 수정 소스는 원래 바이트/해시로 복구했다.

이 배치는 S2930 25개 위치를 수정한다. Windows native 글꼴/DC/프린터 핸들, 전송 코드의 CoTaskMem 할당, 공유 static 상태와 실장비 연속 출력은 후속 작업이다. 실장비의 USB/TCP/Serial/드라이버 출력·커터·장시간 메모리/핸들 검증은 아직 완료하지 않았다. 모든 자원 누수가 해소됐다는 의미로 사용하지 않는다.

영향 범위는 같은 라이브러리를 사용하는 모든 소비자다. 변경된 공용 커밋을 먼저 push한 후 소비 저장소가 포인터를 갱신한다. 롤백은 소비 저장소의 포인터를 위 기준 커밋으로 되돌리는 것이며, 이미지 누수도 복원되므로 현장 장애 대응 시 함께 기록한다. Sonar 서버 재분석은 소비 저장소의 정확한 포인터와 분석 revision으로 확인한다.

## .NET 10 테스트 전환 통합 (2026-09-07)

EventGate develop에 .NET 10 전환이 반영되어, 공용 main의 `9dff12147d61a2ea77b45dcbd585485a5653f7a1`을 이미지 수정 브랜치에 병합했다. 이미지 수정과 공개 라이브러리의 netstandard2.0을 유지하면서 공용 테스트 대상/도구만 main과 같이 net10.0-windows로 맞췄다. SDK 10.0.400에서 26개 테스트가 통과했다. 이미지 변경을 되돌릴 때 .NET 10 테스트 전환을 유지하려면 소비자의 포인터를 `9dff1214`로 되돌린다.

## PRN-02A TCP 연결 상태 분리 (2026-09-07)

기준 커밋은 `b6c541631fa723828e3835683c61247ae4a3bf3f`다. `ethernet`의 기본 소켓과 번호 1~5의 소켓·주소가 static이어서, 두 인스턴스를 열면 이전 인스턴스의 명령과 close 호출이 나중에 열린 프린터에 적용됐다. `openport_mult`는 번호별 주소를 만들고도 기본 `ipe`로 연결했으며, 지연 인자가 없는 overload는 실제 TCP 포트 대신 슬롯 번호를 주소에 넣었다.

소켓과 주소 12개를 인스턴스 필드로 옮겼다. 연결·전송·수신·종료는 해당 인스턴스의 필드를 참조한다. 다중 포트의 두 open overload는 지정한 `portnumber`와 슬롯별 주소를 사용하고, 상태 수신도 해당 슬롯의 주소를 사용한다. 공개 메서드 서명, 명령 인코딩·CRLF·반환값, 기존 연결 대기 시간과 timeout 값은 유지한다.

`EthernetConnectionTests`는 실제 loopback TCP 서버와 임시 포트를 사용한다. 운영 프린터·고정 포트·DB를 사용하지 않는다. 정상 인스턴스 두 개의 동시 20회 출력, 종료 격리, close 후 재연결, 기본 연결 없이 각 1~5번 슬롯 연결(두 overload), 서로 다른 인스턴스의 같은 슬롯, 기본+5개 슬롯의 명령·상태 응답, 잘못된 슬롯의 기존 반환값을 검사한다. 기존 코드에서는 19개 중 17개가 실패했고 수정 후 19개가 통과했다. 같은 테스트 소스를 EventGate.Printer.Tests에 연결한다.

추가로 명령 인코딩·설정·파일 전송의 고정 바이트, 기기 정보·문자열 상태 조회, ACK 종료 응답을 검증하여 TCP 테스트를 37개로 확장했다. 공용 전체 63개·EventGate 프린터 전체 96개가 통과했다. OpenCover와 수정 diff를 대조하면 변경된 실행 지점 266개 중 246개가 실행됐으며, 이는 Sonar의 라인·분기 coverage 수치와 구별한다.

이 배치는 TCP 연결의 소유 범위를 수정한다. 동일 인스턴스에 대한 동시 호출, close 없이 다시 open할 때의 이전 소켓 수명, 연결 실패·취소 및 BeginConnect/EndConnect 처리, 진단 문자열과 GDI raster의 나머지 공유 상태는 후속 배치다. `printersetting_mult`가 번호별 소켓에 쓰고 기본 소켓의 ReadToStream으로 읽는 문제도 별도 수정·테스트가 필요하다. Microsoft의 [BeginConnect 계약](https://learn.microsoft.com/en-us/dotnet/api/system.net.sockets.socket.beginconnect)은 EndConnect로 완료하도록 명시한다. 기존 코드에는 완료 호출이 없으며 이번 상태 분리만으로 이를 해결했다고 간주하지 않는다. USB/Serial/드라이버 연결과 실제 TCP 프린터의 출력·커터·장시간 검증도 별도로 남는다.

영향은 공개 TCP SDK를 사용하는 소비자다. 서로 다른 인스턴스 사이에서 전역 연결을 공유하던 호출자는 같은 인스턴스로 open/send/close를 수행해야 한다. EventGate의 현재 고수준 TSCPrinter wrapper는 USB를 사용하며 TCP를 직접 생성하는 업무 호출은 저장소 검색에서 발견되지 않았다. 외부 소비자와 실장비 검증 전 NuGet 릴리스·main 병합은 수행하지 않는다. 롤백은 공용 커밋 revert 또는 소비자의 포인터를 위 기준 커밋으로 되돌리는 것이다.

### PRN-02A 조회 중복과 EOF 후속 수정

첫 부모 분석 `8ba9e2ce`에서 S2696 24개가 FIXED였으나 신규 중복률 4.46521%로 Gate가 실패했다. `printercodepage(int)`와 mileage/name/file/memory/serial의 기본·지연 overload, 총 11개의 같은 ASCII 요청/수신 루프를 `QueryPrinterText`로 모은다. 명령 문자열, 기본 1초/호출자 지정 지연, 256바이트 버퍼, Poll 5000, SocketException의 `-1` 반환을 유지한다.

기존 루프는 상대가 송신을 종료하면 Receive가 0을 반환해도 반복했다. EOF에서는 종료하고 받은 텍스트가 있으면 반환하며 없으면 `-1`을 반환한다. 응답 없음·응답 후 종료 두 테스트가 기존 구현에서 모두 3초 시간 초과로 실패했음을 확인했다. 테스트의 finally에서 소켓을 닫아 실패한 실행의 루프도 종료했다. 번호별 설정 조회와 BeginConnect 완료 처리 등 앞서 기록한 잔여 문제는 별도 배치다.

수정 후 EOF 두 경우와 기존 명령·응답 테스트를 포함한 공용 전체 65개·EventGate 프린터 98개가 통과했다. EOF 테스트는 half-close 전에 얻은 NetworkStream으로 요청 바이트를 확인한다. TCP 테스트는 총 39개이며, 기존 37개의 명령·반환값 검증도 유지했다.

## PRN-02B TCP 응답 격리와 종료 (2026-09-07)

기준 공용 커밋은 `d1eb0ba0f523e814bfaabb785080e5c78bb8e67e`다. 세 ReadToStream overload의 전역 `byte_to_string`을 없애고 요청별 StringBuilder와 명시적인 수신 소켓으로 응답을 반환한다. EOF에서 종료하고 ACK·ENDLINE은 제외하며 실제 받은 바이트만 문자로 변환한다. 기존의 byte→char 변환과 소켓 수신 timeout 시 부분 응답 반환을 유지한다.

번호별 설정 조회는 지정한 소켓에서 응답을 받고 기본 설정 조회와 같은 CRLF·ACK 요청을 보낸다. 잘못된 번호/열리지 않은 설정 조회 연결은 `error`를 반환한다. 이전의 미완성 명령 프레임, 기본 소켓 응답 또는 다른 요청의 과거 문자열을 반환하던 동작은 결함으로 수정한다. 공개 메서드와 기본 조회의 명령 바이트·delay overload는 유지한다.

신규 Loopback 회귀 테스트 36개는 기존 코드에서 26개 실패·10개 통과, 수정 후 전부 통과했다. 번호 1~5와 기본 연결 유무, 동시 요청의 텍스트 격리, EOF·timeout, 1024바이트 경계와 다음 응답, NUL·0x80·0xff 보존을 검증한다. C# 7.3·netstandard2.0을 유지한다.

기존 테스트를 포함한 공용 전체 101개와 EventGate 프린터 소비자 134개가 통과했다. 소비자의 OpenCover에서 변경 실행 지점 54개 중 51개 실행을 확인했다. 이는 Sonar의 라인·분기 coverage 수치와 구별하며 남은 취소·연결 수명의 검증을 대신하지 않는다. 부모 포인터를 고정한 서버 재분석 결과는 EventGate의 변경 기록에서 추적한다.

같은 소켓의 동시 호출, reopen·BeginConnect 완료/실패/취소, 다른 연결 방식과 GDI 상태는 남아 있다. 실장비와 외부 소비자 검증 전 NuGet 릴리스·main 병합을 수행하지 않는다. 롤백은 소비자의 공용 포인터를 위 기준 커밋으로 되돌리는 것이며 전역 응답 간섭과 EOF 반복도 복구된다.
